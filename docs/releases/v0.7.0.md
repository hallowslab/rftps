Breaking release - replication/plumbing extraction and a clearer startup contract.

### Breaking changes

- **`FtpServer::run` now takes a readiness channel:**
  `run(self, stop_rx, ready: Option<oneshot::Sender<Result<(), String>>>)`.
  Callers passing the old single-argument form must update (the CLI passes
  `None`).
- **Shared plumbing moved to `exifflow-core`.** The event bus, durable record
  store, and path/IP utilities now live in the separate `exifflow-core` crate,
  consumed as a git dependency. `rftps` re-exports them, so existing
  `rftps::event::...`, `rftps::record::...`, and `rftps::utils::...` paths keep
  working.

### Changes

- **Default control port `21212` -> `41212`.** `21212` can fall inside a
  Hyper-V/WSL/Docker-reserved range on Windows and fail to bind. `41212` sits in
  the registered band, clear of the usual excluded and ephemeral ranges.
- **Bind errors are surfaced instead of swallowed.** `run` preflights the
  control-port bind and reports the failure through the readiness channel; build
  failures are reported the same way. The GUI no longer claims "started" for a
  port that never bound.
- **Windows hint for `WSAEACCES` (os error 10013):** the error now points at
  `netsh interface ipv4 show excludedportrange protocol=tcp`.
- **Dependencies:** removed `rand`, `serde`, and `rusqlite` (moved to
  `exifflow-core`); added `exifflow-core`.
- **Release artifacts:** the `-plain` binary is now built with no features (HTTPS
  needs `--cert-pem`/`--key-pem`); the `-full` binary embeds certificates
  (`include-pem-files`).

### Removed (stale in CI/docs)

- The `s3` and `broker` cargo features no longer exist. Replication lives in the
  standalone `replicator-rs` worker; `rftps` only records uploads to the durable
  store (`--record-store`).

### Notes

- FTP behavior and CLI flags are otherwise unchanged; existing configs keep
  working, though installs that persisted the old default port keep `21212`.
